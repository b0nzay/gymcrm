# Описание

Мини-CRM для спортивного зала: клиенты, абонементы, посещения, оплаты и журнал действий

Проект начинался как заказ для конкретного зала. До продакшена он не дошёл: у заказчика так и не появился сервер, на который можно было выкатить систему. Эта учебный публичный вариант

Исходное ТЗ лежит в [docs/spec.md](docs/spec.md)

## Стек

- Backend: Django 6, Django REST Framework, SimpleJWT, PostgreSQL, WhiteNoise
- Frontend: React 19, Vite, React Router
- Установка на телефон заявлена как PWA, но не доделана полноценно: есть манифест и service worker

## Роли

| Роль | Что может |
|---|---|
| Клиент | Регистрируется по коду зала, видит свой абонемент и историю посещений |
| Тренер | Ищет клиентов, выдаёт абонемент, отмечает визит, пишет заметки. Отмену абонемента и визита можно сделать только в течение 24 часов |
| Администратор | Всё то же, плюс планы, оплаты, статистика, журнал, ротация кода зала, управление сотрудниками. Ограничений «24 часа» нет |

Клиенты не ходят в чужие карточки, статистику и логи - это закрыто на API.

## Как запустить локально

Нужны Python 3.12+, Node.js, PostgreSQL.

1. Создайте базу, например `gymcrm`.
2. Скопируйте `.env.example` в `.env` и заполните `DJANGO_SECRET_KEY` и `POSTGRES_PASSWORD`
3. Установите зависимости и примените миграции:

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
```

4. Создайте пользователя с ролью admin в Django Admin (`/admin/`). Обычный `createsuperuser` даёт доступ в `/admin/`, но роль в приложении задаётся полем `role`.
5. Поднимите API:

```bash
python manage.py runserver
```

6. В другом терминале соберите или запустите фронт:

```bash
cd gymcrm-web
npm install
npm run dev
```

Vite ходит на `http://127.0.0.1:5173` и проксирует `/api` на Django.

> Чтобы открывать всё с одного адреса Django, соберите фронт (`npm run build` в `gymcrm-web`) - WhiteNoise отдаёт `gymcrm-web/dist`.

После входа администратором в приложении сгенерируйте код зала и уже с ним регистрируются клиенты.

## Что сделано

- Регистрация по коду зала и вход по логину/паролю (JWT)
- Один активный абонемент на клиента, списание посещений, истечение срока
- Планы, оплаты, заметки персонала, журнал действий
- Тёмная тема, календарь посещений у клиента

## Чего нет

- Полноценный PWA: service worker почти пустой, офлайна нет. Планировалась доработка, но до нее не дошло
- Публичного demo-стенда
- Часть ТЗ не вошла в код и была упрощена
