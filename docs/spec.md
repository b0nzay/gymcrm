# Система управления спортивным залом

Необходимо разработать web-приложение для спортивного зала с поддержкой ролей, абонементов, посещений, оплат и внутренней информации о клиентах.

Система должна работать через браузер на:

* Android
* iOS
* Windows
* macOS

Приложение должно поддерживать установку на телефон как PWA (Progressive Web App).

---

# Общая логика системы

В системе хранится:

* база клиентов
* информация об абонементах
* посещения
* оплаты
* служебные заметки
* история действий пользователей

Система имеет 3 роли:

* клиент
* тренер
* администратор

---

# Авторизация и регистрация

Авторизация осуществляется по:

* номеру телефона
* паролю

Регистрация:

* клиент может зарегистрироваться самостоятельно
* либо тренер может создать аккаунт клиента вручную

При регистрации требуется ввести:

* код доступа спортивного зала

Особенности кода доступа:

* код общий для зала
* код можно изменить через админку
* код может генерироваться автоматически
* старый код после изменения перестаёт работать

SMS-подтверждение номера телефона не используется.

Номер телефона:

* уникален для каждого пользователя
* может быть изменён пользователем позже

---

# Роль: Клиент

Клиент после входа может:

## Просмотр абонементов

* смотреть список доступных абонементов
* смотреть текущий активный абонемент
* смотреть количество оставшихся занятий
* смотреть срок действия абонемента

## Просмотр посещений

* календарь посещений
* дни посещений отмечаются точками
* при нажатии на день отображается:

  * дата
  * время посещения

## Профиль

Клиент может:

* загрузить фото профиля
* изменить номер телефона
* изменить дату рождения
* редактировать информацию о заболеваниях

В профиле отображается:

* ФИО
* дата рождения
* возраст
* телефон
* фото
* заболевания

Поле "заболевания":

* видит сам клиент
* видят тренеры и администраторы
* не видят другие клиенты

---

# Роль: Тренер

Тренер может:

## Поиск клиентов

* поиск по ФИО
* поиск по номеру телефона

## Карточка клиента

Тренер может открыть карточку клиента и видеть:

* личные данные
* заболевания
* текущий абонемент
* количество оставшихся занятий
* историю посещений

## Действия с клиентом

Тренер может:

* отмечать посещение
* выдавать абонемент
* создавать клиента вручную
* добавлять служебные заметки

При отметке посещения:

* уменьшается количество оставшихся занятий

Если:

* занятия закончились
* или срок абонемента истёк

то отметить посещение нельзя.

## Служебные заметки

Служебные заметки:

* видны только тренерам и администраторам
* содержат автора заметки
* содержат дату и время создания

## История действий

В карточке клиента отображается:

* кто выдал абонемент
* кто отметил посещение
* кто добавил заметку

Клиент не имеет доступа к этой информации.

---

# Роль: Администратор

Администратор имеет весь функционал тренера, а также:

## Управление клиентами

* удаление клиентов

## Логи системы

Просмотр истории действий:

* кто выполнил действие
* какое действие выполнено
* дата и время действия

Поддерживаются фильтры:

* по клиенту
* по тренеру
* по дате

## Оплаты

Администратор может добавлять информацию об оплатах:

* клиент
* абонемент
* сумма
* дата
* кто добавил запись
* комментарий

Комментарий может содержать:

* номер перевода
* способ оплаты
* любую служебную информацию

Абонемент можно выдать:

* как с оплатой
* так и без оплаты

## Статистика

Простая статистика:

* сумма оплат за период
* количество посещений
* активность тренеров
* количество отмеченных посещений по тренерам

---

# Абонементы

Абонементы задаются заранее администратором.

Каждый абонемент содержит:

* название
* количество занятий
* срок действия в днях

Примеры:

* 8 занятий / 30 дней
* 12 занятий / 30 дней

При выдаче тренер выбирает абонемент из списка.

---

# Безопасность и ограничения

## Ограничение доступа

Система не должна индексироваться поисковыми системами.

Регистрация доступна только при наличии актуального кода доступа.

## Изоляция окружений

Проект должен иметь:

* production окружение
* demo окружение

Demo окружение:

* полностью изолировано от production
* использует отдельную базу данных
* использует отдельные медиафайлы
* используется для портфолио и тестирования новых функций

Доступ к demo:

* только по отдельной ссылке
* только через логин и пароль demo-аккаунтов
